## HW01 — 휴대전화 없이 가상 패드 확인

1. Codex가 만든 Windows Probe를 빌드합니다. 공식 설치본을 사용한 드라이버의 서명과 로드 상태를 확인합니다. 설치 실패 시 Windows/드라이버 버전과 정확한 오류를 기록합니다.
2. 연결 전 XInput 슬롯을 관찰한 뒤 가상 Xbox 패드 하나를 만듭니다. 새 슬롯과 Probe의 테스트 순서를 대응시킵니다. 설치 프로그램만 실행해 놓고 패드가 생성됐다고 간주하지 않습니다.
3. `python tools/xinput_probe.py --seconds 30 > xinput.csv`로 읽습니다. 출력하는 모든 슬롯 중 시험 장치의 슬롯만 판정합니다.
4. 중립, 좌·우 50%, 좌·우 100%, 브레이크 50%, 가속 50%, 동시 100%, 중립을 각각 1초 이상 유지합니다. 주변 게임을 조작할 수 있으므로 게임 주행 중에 무심코 진단을 실행하지 않습니다.
5. 기대값: LX -32768/0/32767, 반 입력 약 -16384/+16384, LT/RT 반 입력 128, 동시 LT=255와 RT=255. 두 트리거 중 하나만 읽히거나 둘이 상쇄되면 FAIL입니다.
6. Probe 종료 후 가상 슬롯 해제 또는 중립을 확인합니다. 예외 종료와 강제 종료도 별도 시험합니다. read error 1167 등 연결 해제 상태를 중립 정상 연결과 구분합니다.

합격: 독립 트리거와 축 값이 XInput으로 관찰되고, 종료 뒤 가속/버튼이 남지 않음. `joy.cpl`만 통과한 것은 합격 증거가 아닙니다. 아직 이 검증을 수행하지 않았습니다.

## HW02 — 게임이 입력을 어떻게 처리하는지 확인

F1 2026 Season Pack과 원작 AC를 각각 실행합니다. 가상 패드를 게임 실행 전 연결한 상태부터 시험합니다. 슬롯/매핑 충돌이 있으면 실제 패드·중복 매퍼의 영향을 한 변수씩 분리합니다.

게임의 입력 설정 화면에서 LX/브레이크/가속을 확인하고 동시 100%가 표시되는지 봅니다. 패드 감도·필터·조향 속도 보정·데드존·감마·saturation을 기록합니다. 휴대전화 대신 Probe를 써서 가상 입력 처리 문제와 센서 문제를 분리합니다.

좌우 25/50/100%의 일정 입력 및 단계 전환을 저속 직선에서 비교합니다. 입력값은 즉시 바뀌는데 게임 조향은 늦게 변하는지, 속도에 따라 조향 최대값이 줄어드는지 관찰합니다. Cockpit 휠 애니메이션만을 물리 바퀴각의 정확한 측정값으로 쓰지 않습니다.

합격: 두 게임에서 매핑·아날로그 동시 입력 가능, 사용자에게 조향 응답이 허용 가능. 게임별 통과를 각각 기록합니다. 한 게임만 통과했다면 둘 다 호환된다고 표시하지 않습니다. 안티치트가 드라이버를 차단하는 경우 오류를 남기고 지원 경로를 재검토합니다.

## HW03 — 센서와 각도

센서 목록·이름·제조사·minDelay·resolution·보고 모드·실제 timestamp를 저장합니다. 200Hz 요청이 실제로 200Hz인지 확인하고, 센서 간격과 콜백 간격 각각 p50/p95/p99/max를 계산합니다. 배치 전달은 센서 timestamp가 고르게 보여도 콜백이 몰릴 수 있습니다.

화면을 수직에 가깝게 고정할 수 있는 회전 지그와 각도 눈금을 사용합니다. 0/±15/±30/±60/±90도에서 각 5초, 3회 반복합니다. 오른쪽으로 돌릴 때 조향이 오른쪽인지 먼저 확인합니다. 상대 회전의 물리 기준을 직접 기록합니다.

기준 자세 60초와 10분을 각각 측정하고 중앙 복귀 오차, RMS, drift를 분리합니다. 손으로 들고 측정한 떨림을 센서 자체 오차라고 부르지 않습니다. 실제 사용 자세 실험을 별도로 하고 수평에 가까운 자세와 비교합니다.

초기 목표: 평균 절대오차 ≤2°, 고정 RMS ≤0.5°, 10분 기준 복귀 오차 ≤2°. 임의 자동 recenter로 결과를 좋게 만들지 않습니다. 목표와 실제 오차를 모두 남깁니다.

## HW04 — 터치 페달

양쪽을 각각 0/25/50/75/100%로 움직여 단조성과 해제값을 봅니다. 둘을 동시에 100%로 유지합니다. pointer 1→2 진입 및 해제 순서를 바꿉니다. 한 손가락을 다른 영역으로 넘어가게 하고 제3의 손가락을 추가합니다.

페달 30%를 유지하며 ±45° 조향을 10회 반복합니다. 페달값 변동과 실제 손가락 움직임을 영상으로 비교합니다. 이 실험에서 반복 오차가 크면 센서 교체보다 UI 스트로크·앵커·그립 자세를 먼저 조정합니다.

손을 떼기, 시스템 제스처, 알림으로 Activity가 비활성화되기, 앱 전환, 화면 잠금, 창 크기 변경, 접기/펼치기를 각각 시험합니다. 취소 후 양쪽 값·버튼이 0인지 확인합니다. 지원하지 않는 형태에서는 재보정 안내를 표시합니다.

## HW05 — 장애와 재활성화

모의 송신기로 올바른 패킷, 잘못된 MAC, 다른 세션, NaN, 범위 초과, 잘린 패킷, 중복, 역순, uint32 wrap을 주입합니다. 무효 패킷이 출력이나 정상 수신 시간을 갱신하지 않는지 확인합니다. 정상 세션을 시작하지 않은 외부 패킷에는 패드를 생성하지 않습니다.

가속 100%를 유지한 상태에서 테스트용 송신을 중단하고 PC의 마지막 유효 수신→중립 제출 시간을 측정합니다. 150ms 정책이 스케줄링 지연을 포함해 170ms 이내에 적용되는지 봅니다. 게임 부하가 높은 조건에서도 반복합니다.

100/200/500ms 지연, 1/5/10% 손실, 중복·역순을 각각 재현합니다. 오래된 challenge를 가진 새 sequence가 거부되는지 확인합니다. 수신 콜백이 전혀 오지 않는 경우에도 watchdog이 작동해야 합니다.

복구 직후 ARM=1과 가속 100% 패킷이 계속 와도 출력은 중립이어야 합니다. ARM=0·중립 300ms 후 새 시작 동작으로만 활성화되는지 확인합니다. 보정 epoch 변경, 폰 앱 종료·재시작, PC 동반 앱 종료·재시작도 시험합니다.

## HW06 — 지연 비교

USB 테더링 네트워크와 Wi-Fi를 같은 앱 빌드·차량·게임 설정·fps·모니터 조건에서 비교합니다. 조건별 최소 30회 조향 시작과 페달 시작/해제를 측정합니다. 빠른 조건만 선택하여 대표값으로 제시하지 않습니다. p50/p95/p99/max와 표본 수를 기록합니다.

기본 로그는 폰 송신→PC ACK 수신의 RTT, PC 수신→가상 패드 제출의 같은 PC 시계 구간을 구분합니다. 독립 시계의 값을 직접 빼지 않습니다. 폰↔PC 구간이 짧은데 게임 화면이 느리면 패드 보정과 렌더링을 확인합니다.

가능하면 240fps 영상 한 화면에 폰의 물리적 움직임과 모니터를 같이 찍습니다. 한 프레임은 약 4.17ms이므로 경계 선택과 화면 스캔아웃의 오차를 포함해 보고합니다. 모니터 변화를 특정하는 일관된 기준을 먼저 정합니다. F1 조향 애니메이션을 기준으로 삼았다면 그 지표의 한계를 적습니다.

초기 목표는 물리 입력→관측 화면 p95 60ms 이내입니다. 측정 전 “5ms/10ms 지연” 같은 수치를 제품 성능으로 쓰지 않습니다. RTT 절반이 실제 one-way 또는 motion-to-photon이 되는 것은 아닙니다.

## HW07 — F1 텔레메트리와 판정 의미

공식 EA 문서와 설치 게임 버전을 기록합니다. 게임 설정에서 2025 UDP를 선택하고 실제 header format이 2025인지 확인합니다. 참조 파서가 받는 Motion Ex 273바이트를 실캡처에서 확인합니다. 합성 fixture가 통과했다는 사실로 대체하지 않습니다.

직선 정지→전진, 가속·감속, 좌·우 회전, 잠김 유발, 구동륜 헛돎 유발, 연석, 리플레이, 일시정지, flashback을 짧게 캡처합니다. 실험은 게임 안에서 시행합니다. TC/ABS OFF와 ON을 각각 비교하고 설정을 원래 사용자 선호로 복구합니다.

wheel 순서, slip 부호·범위, 어떤 바퀴가 구동륜인지, 접지·속도 조건을 확인합니다. 잠김/헛돎 시각은 영상과 함께 수동 표기해 검출 지연과 오경보를 계산합니다. 정상 코너링도 슬립이 있으므로 절댓값 증가만으로 위험으로 분류하지 않습니다.

문서 필드 의미를 확인하지 못했거나 두 사건이 분리되지 않으면 그 검출기는 disabled를 유지합니다. assist 설정값을 개입 이벤트로 대체하지 않습니다. 2026 전용 형식 추가 시 모든 구조체/길이를 새로 대조하고 별도 실캡처를 확보합니다.

## HW08 — Assetto Corsa

원작 AC의 공식 SDK 또는 Kunos 원문을 확보한 뒤 `gameVersion`, `sharedMemoryVersion`, 구조체 size와 필요한 field offset, wheel 순서, 단위, packing, 문자열 규칙을 기록합니다. 자료가 없으면 BLOCKED 또는 NOT RUN입니다. ACC/EVO 자료로 원작 검증을 통과시키지 않습니다.

속도·페달·주행 상태를 먼저 화면과 대조합니다. 메모리 샘플을 과도한 빈도로 반복 읽는 것을 실제 게임 갱신률이라고 부르지 않습니다. 읽기 일관성, packet ID 변화, 게임 종료·재시작, 리플레이·일시정지를 확인합니다.

`wheelSlip`의 의미가 충분히 확인되지 않으면 해당 값으로 잠김/헛돎을 분류하지 않습니다. 계산으로 보완한다면 반지름·각속도·차량 속도 단위와 전진 부호를 직선부터 대조합니다. 차종마다 프로필을 분리합니다.

## HW09–10 — 진동 식별과 입력 간섭

진동 모터/효과/진폭 제어 능력을 덤프합니다. 약/중/강을 편한 세기로 보정하고 잠김·헛돎 패턴을 설명한 뒤, 무작위 순서 20회에서 화면 단서를 가린 상태로 이벤트를 맞힙니다. 이어서 조향·페달을 같이 조작하며 반복합니다. 16/20은 초기 목표일 뿐 통계적 보편 성능 보증이 아닙니다.

연석→잠김, 엔진/변속 OFF, 잠김 중 저우선 이벤트, 같은 이벤트 30Hz 갱신, 연결 단절을 시험합니다. 경고가 종료된 뒤 밀린 연석·변속 진동이 재생되면 FAIL입니다. heartbeat마다 패턴이 처음부터 반복되는지도 확인합니다.

같은 물리 자세에서 진동 OFF/ON 순서를 번갈아 최소 5회, 각 30초 측정합니다. 각도 RMS·최대 편차·페달 유지 오차를 비교합니다. 고정 지그와 실제 손에 든 상태를 따로 기록합니다. 간섭이 보이면 먼저 진동 세기·재생 빈도를 줄여 비교하고, 필터 수정이 조향 지연을 늘리는지도 다시 측정합니다.

## HW11 — 사용자 판단

30분 주행 동안 센서율, 콜백 지연, 송수신 간격, CPU·열 상태, 메모리, 연결 단절, 반복 오경보를 기록합니다. 앱 종료·복귀, 절전·복귀, 케이블 제거 후 이전 가속이 자동 재개되지 않는지 확인합니다.

최종 사용성 질문: 직선 중앙 유지가 가능한가, 코너에서 가속·브레이크를 원하는 비율로 유지할 수 있는가, 손/손목 피로가 허용 가능한가, 진동을 구별하고 대응할 수 있는가. 랩타임 개선은 보너스 평가이며 필수 결과로 가정하지 않습니다.

새 휴대전화 구매는 원인별로 판단합니다. PC 조향 필터·드라이버·Wi-Fi가 병목이면 폰 교체로 해결된다고 볼 수 없습니다. 터치 페달 조작 자체가 어려우면 실제 페달 등 별도 입력 장치가 더 직접적인 개선일 수 있습니다.
